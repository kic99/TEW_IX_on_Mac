# Total Extreme Wrestling IX on an Apple Silicon Mac (Wine)

Tested on an M5 Max with macOS 27.0.1, Wine 11.18 Staging (Gcenx build), winetricks 20260125, and TEW IX retail 1.4.21.

Everything goes in one folder, `~/tew9`. Run the commands in Terminal, in order. Total time is about 20 to 30 minutes, mostly downloads and the library installs.

In the interest of full disclosure, what follows is generated by Claude. Take that as you will, but know that it does work.

---

## Quick install (recommended)

A script does every step of the manual guide below for you. It takes about 5 to 15 minutes, depending on your connection.

1. Make sure you have [Homebrew](https://brew.sh) and your TEW IX installer (`.msi`) from Grey Dog Software.
2. Download this repo: click the green *Code* button, then *Download ZIP*, and unzip it.
3. Open Terminal, type `bash ` (with a space after it), drag `install.sh` from the unzipped folder into the Terminal window, type another space, drag in your `.msi`, and press Return. It looks like this:

   ```sh
   bash ~/Downloads/TEW_IX_on_Mac-main/install.sh ~/Downloads/TEW9_Retail_Installer_142.msi
   ```

4. If macOS asks whether Terminal may access your Downloads folder, click **Allow**. If Rosetta 2 is missing, the script asks before installing it.
5. When it prints `Done`, start the game with **TEW9** in your Applications folder (`~/Applications`), or type TEW9 in Spotlight. On first launch, activate your licence in the License Wizard (see step 6 below).

The script puts everything in `~/tew9`, the same as the manual guide, so the Troubleshooting and Uninstall sections below apply. It checks every download and step, and stops with a message if something fails. The full log is in `~/tew9/install.log`. Running it again skips the steps that already finished, so after fixing a problem (for example, a failed download), just rerun the same command.

The rest of this page is the manual install, and it also explains what the script does.

## What you need

- An Apple Silicon Mac with **Rosetta 2**. Check with `arch -x86_64 /usr/bin/true && echo ok`. If that fails, run `softwareupdate --install-rosetta --agree-to-license`.
- **Homebrew**. [Brew's website](https://brew.sh)
- About 4 GB of free disk space.
- The **TEW IX installer** (`.msi`) from Grey Dog Software, and your licence key.
- The **`wow64cpu-rosetta-fix`** folder from `https://github.com/kic99/TEW_IX_on_Mac`. Either clone this locally, or go download the files manually (click the green *Code* drop-down button, select *Download ZIP*).
- Optional: the **`wine-mac-redraw`** folder from the same repo, copied into `~/tew9`. It rescues a blank game window (see Troubleshooting).

## 1. Install Wine and winetricks

```sh
export TEW="$HOME/tew9"
mkdir -p "$TEW/downloads" "$TEW/wine"
cd "$TEW"
curl -fL -o downloads/wine-staging-11.18-osx64.tar.xz \
  https://github.com/Gcenx/macOS_Wine_builds/releases/download/11.18/wine-staging-11.18-osx64.tar.xz
shasum -a 256 downloads/wine-staging-11.18-osx64.tar.xz
# b63704b91af269bc026a87f12bd297c4a50caaf570c322e600b6621ef918f127
tar -xJf downloads/wine-staging-11.18-osx64.tar.xz -C wine/
xattr -dr com.apple.quarantine "wine/Wine Staging.app"

brew install winetricks
```

Create the environment file and load it:

```sh
cat > "$TEW/tew-env.sh" <<EOF
export TEW="$TEW"
export PATH="\$TEW/wine/Wine Staging.app/Contents/Resources/wine/bin:\$PATH"
export WINEPREFIX="\$TEW/wineprefix"
export WINEDEBUG=-winediag
EOF
. "$TEW/tew-env.sh"
wine --version          # wine-11.18 (Staging)
```

In any new Terminal window, run `. ~/tew9/tew-env.sh` first.

## 2. Install the Rosetta fix

Copy the `wow64cpu-rosetta-fix` folder into `~/tew9`, then:

```sh
cd "$TEW/wow64cpu-rosetta-fix"
```

## 4. Install the libraries

Install all of these **before** the game.

### 4.1 MDAC 2.7

```sh
. ~/tew9/tew-env.sh
mkdir -p ~/.cache/winetricks/mdac27 && cd ~/.cache/winetricks/mdac27
curl -fL -o MDAC_TYP.EXE \
  "https://web.archive.org/web/20060718123742/http://ftp.gunadarma.ac.id/pub/driver/itegno/USB%20Software/MDAC/MDAC_TYP.EXE"
shasum -a 256 MDAC_TYP.EXE
# 36d2a3099e6286ae3fab181a502a95fbd825fa5ddb30bf09b345abc7f1f620b4

for d in msado15 odbccp32 mtxdm odbc32 oledb32; do
  wine reg add "HKCU\Software\Wine\DllOverrides" /v "*$d" /t REG_SZ /d native,builtin /f
done
cabextract -q -d "$WINEPREFIX/drive_c/windows/temp/mdac27x" MDAC_TYP.EXE
winetricks -q -f nt40
cd "$WINEPREFIX/drive_c/windows/temp/mdac27x"
wine setup.exe /qnt ; echo "exit=$?"        # exit=0, takes about a minute
ls "$WINEPREFIX/drive_c/Program Files (x86)/Common Files/System/ADO/msado26.tlb"
```

### 4.2 WSH 5.7 and Jet 4.0

```sh
curl -fL -o jet40sp8_9xnt.exe \
  "https://web.archive.org/web/20210225171713/http://download.microsoft.com/download/4/3/9/4393c9ac-e69e-458d-9f6d-2fe191c51469/Jet40SP8_9xNT.exe"

# b060246cd499085a31f15873689d5fa7df817e407c8261a5c71fa6b9f7042560
wine jet40sp8_9xnt.exe /q ; echo "exit=$?"   # exit=0

winetricks -q win10
printf 'mdac27\njet40\n' >> "$WINEPREFIX/winetricks.log"

```

### 4.3 VB6 runtime, oleaut32, .NET 4.8

```sh
wine reg add 'HKCU\Software\Wine\DllOverrides' /v mscorsvw.exe /d "" /f
winetricks -q -f vb6run native_oleaut32 dotnet48
```

The first line stops a .NET background process that would otherwise stall the install (see Technical notes). The install takes about 5 minutes, plus download time.

```sh

#   oleaut32.dll 598,288 bytes, mscoree.dll 297,808 bytes
```

## 6. Create the launcher and start the game

The launcher starts the game from its own folder, keeps the display awake while you play, and cleans up after you quit. Copy and paste this whole block:

```sh
cat > "$TEW/tew9.sh" <<'EOF'
#!/bin/zsh
# Launch TEW9. Keeps the display awake while playing, and ends the game once it and the
# License Wizard have had no windows for 30 seconds (after quitting, the game can linger).
. "${0:A:h}/tew-env.sh"
GAME='Grey Dog Software.TEW9.TEW9\.exe'
ALL='Grey Dog Software.TEW9.'   # the game and its separate License Wizard
cd "$WINEPREFIX/drive_c/Program Files (x86)/Grey Dog Software/TEW9" || exit 1
pgrep -qf "$GAME" && { echo "TEW9 is already running"; exit 0; }
caffeinate -d -w $$ &
wine TEW9.exe "$@" &
pid=""
for i in {1..30}; do sleep 2; pid=$(pgrep -f "$GAME" | head -1); [ -n "$pid" ] && break; done
if [ -n "$pid" ]; then
  seen=0; gone=0; waited=0
  while kill -0 $pid 2>/dev/null; do
    sleep 5; waited=$((waited+5))
    if [ "$(osascript -l JavaScript "$TEW/winewindows.js" $(pgrep -f "$ALL"))" -gt 0 ]; then seen=1; gone=0; else gone=$((gone+5)); fi
    # Gone for 30 s and idle (not still writing the save on quit).
    [ $seen = 1 ] && [ $gone -ge 30 ] && [ "$(ps -o %cpu= -p $pid | cut -d. -f1)" -lt 2 ] && break
    [ $seen = 0 ] && [ $waited -ge 300 ] && break
  done
fi
# End only the game and the wizard, so other programs in the prefix keep running.
if pgrep -qf "$ALL"; then
  wine taskkill /f /im TEW9.exe /im QlmLicenseWizard.exe >/dev/null 2>&1
  sleep 3; pkill -9 -f "$ALL"
fi
EOF

cat > "$TEW/winewindows.js" <<'EOF'
// usage: osascript -l JavaScript winewindows.js <pid> [<pid> ...]
// Prints how many real windows belong to the given processes. Uses only owner PID and size,
// which macOS gives without Screen Recording permission. Skips VB6's hidden 1x1 window and
// Wine's off-screen 500x500 helper windows. From https://github.com/Philsmith1/wmma6-on-mac
ObjC.import('CoreGraphics');
function run(argv) {
  var pids = argv.map(function (p) { return parseInt(p, 10); });
  var list = ObjC.deepUnwrap(ObjC.castRefToObject($.CGWindowListCopyWindowInfo($.kCGWindowListOptionAll, 0))) || [];
  var n = 0;
  list.forEach(function (w) {
    if (pids.indexOf(w.kCGWindowOwnerPID) < 0 || w.kCGWindowLayer !== 0) return;
    var b = w.kCGWindowBounds;
    if (b.Width <= 50 || b.Height <= 50) return;
    if (!w.kCGWindowIsOnscreen && b.Width === 500 && b.Height === 500) return;
    n++;
  });
  return String(n);
}
EOF

chmod +x "$TEW/tew9.sh"
"$TEW/tew9.sh"
```

From now on, start the game with `~/tew9/tew9.sh`. The Terminal window stays busy while the game runs; that is normal.

On first launch, the **License Wizard** opens after 10 to 20 seconds. Click **Activate your license**, enter your key, and activate online. The game then starts.

To quit, use the game's own exit. If Wine ever hangs: `. ~/tew9/tew-env.sh && wineserver -k`.

## Troubleshooting

| Problem | Fix |
|---|---|
| "Wine Staging.app is damaged" | `xattr -dr com.apple.quarantine "$TEW/wine/Wine Staging.app"` |
| `Bad CPU type in executable` | Install Rosetta (see "What you need"). |
| Game window never appears; log shows `nested exception on signal stack` | The Rosetta fix is missing from the prefix. Run `"$TEW/wow64cpu-rosetta-fix/install.sh" "$TEW/wow64cpu-rosetta-fix/prebuilt/wine-11.18/wow64cpu.dll" "$TEW/wine/Wine Staging.app" "$WINEPREFIX"` |
| "Run-time error '5': Invalid procedure call or argument" | Start the game with `tew9.sh`, which runs it from its own folder. |
| "Error 53" at start | .NET is missing. Rerun step 4.3, then reinstall the game (step 5). |
| A winetricks download fails | Put the file in `~/.cache/winetricks/<verb>/` and rerun the command. |
| Game window turns blank white after the Mac's display sleeps (game still running) (not yet confirmed, but possibly sleep related)| `. ~/tew9/tew-env.sh && "$TEW/wine-mac-redraw/redraw.sh"` repaints it without losing progress. The launcher from step 6 keeps the display awake while the game runs, which should prevent it. |
| Wine or the game won't quit | `. ~/tew9/tew-env.sh && wineserver -k` |

## Uninstall

Back up your saves first: `~/tew9/wineprefix/drive_c/Program Files (x86)/Grey Dog Software/TEW9/Databases/<database>/SaveGames/`. Deactivate the licence if you plan to install elsewhere.

```sh
. ~/tew9/tew-env.sh && wineserver -k
rm -rf ~/tew9 ~/.cache/winetricks ~/Applications/TEW9.app
brew uninstall winetricks cabextract p7zip && brew autoremove
```

## Technical notes

These explain why each step is the way it is.

**Wine version.** Wine 11.16 or newer is required. Wine 11.0 to 11.15 crash in `msjet40` under WoW64. macOS Wine can only make 64-bit (WoW64) prefixes, so older Wine with a 32-bit prefix is not an option. The Homebrew Wine casks are disabled (Gatekeeper, September 2026), so the Gcenx build is downloaded directly.

**The Rosetta fix (step 2).** The retail game loads the QLM licence manager (`QlmCLRHost_x86.dll`, 32-bit .NET) every time it starts. Under Wine's WoW64 on Apple Silicon, every 32-bit .NET program hangs at startup with `nested exception on signal stack`, in all Wine versions from 11.0 to 11.18. The cause is in Wine's `wow64cpu.dll`. It switches the CPU between 32-bit and 64-bit mode using far jumps, and Rosetta 2 sometimes does not switch modes on a far jump. The patched DLL uses far returns instead. Plain 32-bit programs, such as the TEW trial (which never loads .NET), are not affected. Details and source are in the `wow64cpu-rosetta-fix` README.

Wine loads `wow64cpu.dll` from the prefix (`C:\windows\system32`), and `wineboot` copies it there from the Wine install. That is why the fix goes into the Wine install before the prefix is created. For an existing prefix, `install.sh` patches both copies.

**MDAC by hand (step 4.1).** `winetricks jet40` installs `mdac27` first. Its self-extractor fails under WoW64 ("Error creating process <setup /qnt>"). Extracting it with `cabextract` and running `setup.exe /qnt` directly works. MDAC's setup needs the Windows version set to NT 4.0, and `winetricks nt40` only changes it with `-f` on a 64-bit prefix. Jet 4.0 SP8 is then installed from its own installer. The two lines added to `winetricks.log` stop winetricks from trying to reinstall them.

**The .NET stall (step 4.3).** During `dotnet40`, .NET starts background "native image" compiler processes (`mscorsvw.exe`). Under Wine they go idle but never exit, and winetricks waits for all Wine processes to end, so the install stalls indefinitely. The empty `mscorsvw.exe` DLL override stops Wine from starting them at all. That is safe: .NET programs compile their code on the fly instead of using precompiled images, and the licence manager works normally. (If you set up a prefix without the override and the install stalls at `wineserver -w`, run `pkill -f mscorsvw.exe` in a second Terminal window.) Thanks to [Philsmith1](https://github.com/Philsmith1) for this tip.

**Library choices (step 4.3).** `vb6run` provides the VB6 runtime and the native `oleaut32.dll`. `native_oleaut32` sets the override that uses it. With Wine's own `oleaut32`, the company-branded frame behind each wrestler photo shows as a plain white box. The wrestler pictures are GIFs whose white border is marked transparent, and Wine's `oleaut32` (11.18 and current development versions) ignores transparency in paletted images, so it draws the border as solid white over the frame. The photos themselves look the same with either version. `dotnet48` (it installs .NET 4.0 first) is needed by the licence manager. `-f` forces these 32-bit installs on a 64-bit prefix. `dotnet48` leaves the Windows version at Windows 7, which is the tested setting.

**Libraries before the game.** Installing the game first and the libraries afterwards leaves a broken install (licence errors).

**Unattended install into Program Files (step 5).** The installer's default folder is `C:\users\<you>\Documents\…`, and Wine maps that to your real macOS `~/Documents`. Passing `APPDIR` with spaces directly to `wine msiexec` fails with exit code 103 (Wine re-quotes the argument), so the command goes through a small batch file.

**Launch from the game folder (step 6).** The licence manager looks for `Total Extreme Wrestling IX 1.0.lw.xml` in the current folder. Started from anywhere else, the game stops with "Run-time error '5'".

**Launcher cleanup (step 6).** After you quit, the game process sometimes stays running with no windows, which also keeps `caffeinate` (and so the display) awake. The launcher checks every 5 seconds whether the game or the License Wizard has a window, using `winewindows.js`. That needs no Screen Recording permission because it reads only window sizes and owners. Once both have had no windows for 30 seconds and the game is idle, it ends them with `taskkill`. It does not run `wineserver -k`, so other programs in the same prefix keep running. The idea and `winewindows.js` come from [Philsmith1](https://github.com/Philsmith1)'s [wmma6-on-mac](https://github.com/Philsmith1/wmma6-on-mac).

**Known Wine issues that do not affect this setup.** A forum report of "Run-time error 481" on Events & TV (Lutris, WoW64), and the list type-ahead bug (Wine bug 42898), did not occur here.
